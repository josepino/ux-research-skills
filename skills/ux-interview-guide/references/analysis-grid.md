# Prepare the analysis grid BEFORE interviewing

**When to read it:** when the guide is ready and there are no sessions yet. Building the grid beforehand avoids analyzing "whatever caught our attention" and forces every data point to connect to the research question. Idea based on third-party interview kits, rewritten.

## 1. Starting codes
Derive them from the research questions (RQs), not from the answers:
- Per RQ, 2-4 codes that name what you need to know (for example RQ "how do they choose where to buy" -> `trigger`, `comparison`, `trust`, `barrier`).
- Add cross-cutting codes: `contradiction`, `surprise`, `strong quote`.
- Leave an "emergent code" column: new codes are normal, but record when and why they appeared.
If you use JTBD, add push / pull / anxiety / habit (`jtbd-timeline.md`).

## 2. Notes template (one row per data point)
| Time/mark | Participant (pseudonym) | Observation (what happened or was said, without interpreting) | Verbatim quote | Interpretation (labeled as such) | Code | RQ |
|---|---|---|---|---|---|---|

Rules: observation and interpretation go in different columns; the quote is literal and carries its timestamp so it can be verified; the interpretation is written as a hypothesis ("could indicate...").

## 3. Insight template
Insight (one sentence with a consequence) · supporting quotes · segment · n of N participants · counter-evidence · implication. When reporting, state the number of participants and the segment.

## 4. Before the first session
- [ ] Every RQ has at least one code.
- [ ] The criterion for calling something a "pattern" is written down (see `funnel-and-quality.md`).
- [ ] Participants appear under a pseudonym; it is clear who keeps the key of equivalences.
After each session: fill the grid the same day (see debrief in `session-conduct.md` section 7). Cross-session synthesis: `ux-synthesis`; quote checking: `ux-insight-qa`; preparing transcripts: `ux-transcript-prep`.
